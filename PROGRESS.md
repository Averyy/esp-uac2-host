## Listening (2026-10-29)

- Setup: miniDSP 2x4 HD into an SVS PB3000 subwoofer. The harness's 1 kHz/440/880 Hz tones are inaudible through it; use 30-120 Hz.
- 14:50 run (6.0.3 duplex build, after a power interruption): tones heard. From about 14:54 even 50-120 Hz tones at -6/-12 dBFS were silent while USB looked normal (48 kHz, clock valid, feedback 48.0, 0 errors). Reflashing the exact firmware that had been audible didn't help; a miniDSP power cycle did. USB replug and ESP32 resets never reset the miniDSP (own power supply).
- miniDSP's dev team (forum, Apr 2026) says the 2x4 HD's DSP takes one input source at a time, so its analog input can't be recorded over USB while USB audio plays. That is not a statement that USB capture during USB playback is unsupported: the manual describes the capture stream as the processed outputs. Once the trigger was found, the harness's duplex streaming check ran on the 2x4 HD (2026-10-30): both streams at full rate, audible throughout, normal playback afterwards. minidsp-open never opens the capture interface.
- XMOS firmware on the unit is 1.85 (`bcdDevice 0x0185`), the latest release for all models (Device Console 1.2.3, Dec 2025); a firmware update is not the fix.
- Our UAC2 start order (clock, then SET_INTERFACE) matches Linux snd-usb-audio; XMOS reference firmware handles rate changes at alt 0. A miniDSP forum thread reports the same stuck-silent symptom on Pi and Mac hosts.
- minidsp-open (fixed 48 kHz, playback only) did not trigger the stuck state across ~40 starts/stops (see Open items), which pointed at harness-only actions; the real trigger (2026-10-30, below) is a reset, which harness sessions do far more often. The harness's thumps were its abruptly cut tones; the stream's own start/stop is silent at the mic.
- Bisect done (see Open items): no single suspect reproduced the stuck-silent state. Diagnostic firmwares (bisect, A/B v0.1.2 vs v0.1.3, final harness) are built under `logs/fw/` (gitignored).
- 2026-10-30, later: the silent state is intermittent. Controlled: a test-only minidsp-open build with its recovery disabled, minidsp-open on both sides, EN cuts mid-stream: 2 of 8 went silent (this tree 1 of 5 with cuts at 5, 5, 15, 15 and 25 s, the 25 s one silent; registry 0.1.3 1 of 3 with cuts at 2, 5 and 15 s, the 15 s one silent). Mixed hosts (harness, example): 0 of 3. That morning's confirmed silent cut came about 8-13 s in, so there's no clear duration threshold. In the stuck state, everything a host can see is normal: enumeration, start, feedback 48.0009, FU 10 mute=false/0 dB, HID memory 0xF000-0xFFFF byte-identical; alt/format, HID source, mute and preset changes and ESP32 resets don't clear it; only the HID reboot does. So the driver can't detect or prevent it; consumers recover with a boot-time stream flag and a HID reboot (minidsp-open c1f0702). Software restarts were 0 of 2
- 2026-10-30, first repros (minidsp-open session, UMIK-1): an ESP32 hardware reset while a playback stream ran, with VBUS up, left the miniDSP silent (intermittent, see the previous entry); USB stays normal and the driver logs nothing. Reproduced twice: a reset during a 40 Hz tone (+54 dB over the room before it), then two sweeps at room level. The first episode was flashing the A harness while the example streamed. Controls: a reset with no stream running left sound fine (peak -0.9 dBFS), and a cable unplug during playback doesn't trigger it (VBUS drops). The 2026-10-29 episode followed a flash mid-session. Every harness run, enumeration and SET_INTERFACE cycle afterwards stayed silent; the miniDSP's own HID reboot (minidsp-open `POST /devices/0/reboot`) cleared it 3 of 3, as a power cycle does. minidsp-open is adding recovery: a stream-active flag that survives the reset, and a HID reboot before audio when a boot finds it set

## v0.1.3 changes

Tests: host parser + packet sizing tests, parser fuzzer (~750M inputs clean), 38 Linux-target driver tests against a fake USB Host Library (ASan/UBSan, hang watchdog, playback payload and capture counter checks, contract-violation counters). Static analysis (GCC `-fanalyzer`, clang-tidy, cppcheck) clean. Reviews: several Dobby rounds plus a full manual pass; findings fixed.

API:
- New: `get_stream_info()`, `get_buffer_status()` (ring/in-flight duration, for latency and drain-before-stop), `set_mute_all_channels()`, `uac2_ep_sync_type_t`, `UAC2_HOST_DUPLEX_FIFO_*`
- `start()` tries every matching alt, best bit depth first; moves on only for alt-specific failures (descriptor checks, packet size > MPS, claim refused because the HCD can't fit the endpoint)
- `start()` returns `ESP_ERR_INVALID_STATE` on an unplugged-but-not-closed handle or one with un-torn-down resources (used to allocate over them)
- Sample rates outside the advertised RANGE (with resolution) are refused (`ESP_ERR_NOT_SUPPORTED`) by start, resume and `set_sample_rate()`; allowed if the RANGE is unreadable or truncated, or with `CONFIG_UAC2_ALLOW_UNADVERTISED_RATES`. Rate read back after SET (warning only)
- `set_sample_rate()` refused while any stream on the device is started/suspended; start/resume refuse a rate different from a sibling stream (shared clock)
- `get_*_range()` treat non-zero `*num_ranges` as capacity (overflowed small arrays before)
- `get_start_time()`/`get_feedback()` return 0 unless ACTIVE and attached; write/read on closed handles return `ESP_ERR_INVALID_STATE`
- `set_volume_all_channels()` continues past a STALLing master control; `set_volume_percent()` snaps to the resolution
- Already-attached devices reported on the first event pass (reinstall without replug); duplicate NEW_DEV within 500 ms dropped, forgotten on DEV_GONE

Device compatibility (from esp32_music_player's CX31993 patches and the airplay-esp32 fork / PR #89):
- 44.1 kHz needs feedback only on async endpoints; adaptive/sync endpoints get the exact 44/45 pattern (`uac2_tx_next_nominal_samples`)
- Clock set before SET_INTERFACE in start and resume (Linux snd-usb-audio's UAC2 order; CX31993 needs it)
- `UAC2_MAX_AS_INTERFACES` 4 -> 8
- Feedback-driven packet sizing at every rate (was fractional rates only)

Playback + capture (opt-in): `CONFIG_UAC2_ALLOW_DUPLEX` lifts the ESP32-S3 guard; the app installs USB Host with `fifo_settings_custom` = 16/90/94 lines (IDF 5.5+/espressif/usb; no runtime setter). Harness `sdkconfig.duplex.defaults` replaces the guard check with a timed duplex stream check.

Fixes (non-obvious causes worth remembering):
- Control timeout: ESP-IDF rejects halt/flush on EP0 and ignores `timeout_ms`, so the URB stays in flight. It's marked abandoned; the next request consumes its late completion; `device_destroy()` orphans it with the device handle (closing with EP0 busy asserts) and the event task reclaims both. Reopen and uninstall refuse meanwhile
- IDF 5.x in-tree USBH notifies control completion before decrementing the in-flight count `usbh_dev_close()` asserts on: 10 ms delay before close on IDF < 6 (espressif/usb >= 1.6.0 fixed; manifest requires it on IDF 6)
- Teardown order: wait for URBs to quiesce, then release the interface. espressif/usb's release sleeps 10 ticks while the client has unprocessed completions (stops took ~100 ms on 6.x); IDF 5.x returns INVALID_STATE (#17707, retry kept). Stopping one stream while another runs can still hit the 10-tick wait
- Zero-tick polling: `pdMS_TO_TICKS(5)` is 0 at 100 Hz; `poll_delay()` sleeps >= 1 tick and wait loops measure elapsed ticks. Linux tests run at 1000 Hz and can't show this
- Ring buffer lifetime: `rw_users` registered before the state check; teardown leaves ACTIVE, wakes callers, waits for 0 before flush/delete
- Disconnect takes `io_users` refs on its interfaces under the driver lock; close unlinks only at 0 refs
- Per-device `stream_mutex` serializes start/resume/set_sample_rate (duplex guard and shared clock)
- Callback errors move only an ACTIVE stream to ERROR; stop sets IDLE after teardown
- Feedback has its own error counter and ignores SKIPPED packets; all-packets-failed URBs count toward the error limit; callback warnings throttled to 1/s
- Lifecycle: static never-deleted mutex for install/uninstall/open/close; background task bound to its installation; uninstall waits only for a running `handle_events()` call
- Parser rejects descriptors ESP-IDF's walker can't handle (bLength < 2, overrun, short INTERFACE/ENDPOINT) and keeps only alts matching what `usb_host_interface_claim()` will use; data EP bInterval must be 1, feedback interval must fit the HCD ISOC list
- Feedback URB alloc/submit failure fails the start; 64-bit `calc_packet_size()`
